Can a factor-graph GNN discover the chain rule?

The optimization model is now represented explicitly as a bipartite graph: variable nodes and > constraint nodes connected by typed operand edges. The GNN receives normalized node IDs, passes messages through the constraint graph, and still chooses the complete joint action (i,v). It never receives the solution as a label.

Graph representation

Two node types

Variable nodes Vᵢ represent xᵢ. Their initial features are node type plus normalized semantic ID i/(n−1).

Constraint nodes Gₖ represent xₖ₊₁ > xₖ. They also receive a node-type bit and normalized constraint ID. For a chain of length n, the graph therefore contains n variable nodes and n−1 constraint nodes.

Four typed edge directions

Operand role is explicit: smaller-variable → constraint, greater-variable → constraint, plus the two reverse directions constraint → smaller-variable and constraint → greater-variable.

Each edge type has its own learned message matrix. Four rounds of residual message passing produce the final embedding for every variable and constraint node.

Action head and RL signal

Joint (i,v) action

The action head receives the final GNN embedding of variable node Vᵢ together with normalized candidate value v/(n−1), then returns one scalar action score. Every possible pair is scored, so the network still chooses both which variable and which value.

The same GNN and action-head parameters are reused at every chain length; only the number of graph nodes and candidate actions changes.

RL, not supervised learning

There are no exact-solution labels. An exploratory action fixes xᵢ=v, then generic bound propagation evaluates the graph constraints. Reward is +1 if the partial assignment remains feasible and −1 if propagation proves a contradiction.

Training remains contextual-bandit RL with ε-greedy exploration and balanced positive/negative replay. The only route from node identity to action value is through the learned GNN representation.

Why this should still be easy

There are exactly n variables, each with domain 0…n−1, and the constraints require a strictly increasing chain. Therefore the unique feasible assignment is x₀=0, x₁=1, …, xₙ₋₁=n−1.

The normalized variable-node ID exposes a simple reusable pattern, while the factor graph now makes the constraint structure explicit. If this version fails, that is evidence about the message-passing/training setup rather than the difficulty of the underlying optimization rule.
