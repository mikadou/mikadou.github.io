Proof of concept · generic learned solver actions

Propose an action, temporarily apply it, then value the resulting solver state

For a selected variable, the learned proposal head generates candidate values. Each candidate is actually applied to a temporary copy of the solver state, the graph is updated, exact immediate improvement is measured, and a shared GNN critic evaluates the resulting successor graph. Actions are ranked by r(s,a,s′) + γV(s′), so immediate solver feedback is used directly while the critic can represent consequences whose reward arrives later.

1. The solver transition is executed, not imagined

For candidate (i,v), the engine clones the current state, applies xᵢ=v, and rebuilds the graph from that successor. In a real CP/MIP adapter, this is the extension point where propagation, domain changes, soft-constraint updates, and objective recomputation would occur. The neural network therefore evaluates the consequences that the solver actually produced.

2. Exact immediate reward + learned future value

The action score is r(s,a,s′) + γV(s′). The immediate term comes directly from the solver adapter, so the critic does not waste capacity predicting effects that can be measured exactly. The value term is trained on discounted return under teacher continuation from both clean and learner-generated states, allowing a successor with little immediate reward to score highly when it leads to better states later.

3. A global solver node carries objective-level state

The graph now contains variable nodes, constraint nodes, and one global solver node connected in both directions. For this toy, the global node carries assignment progress, observed violation rate, violation magnitude, and the adapter-reported objective/quality. A real problem can put objective value, incumbent objective, gap, remaining budget, or other solver-level information in the same place.

4. Proposal learning remains separate

The Gaussian (μ,σ) head is still only a proposal mechanism trained from demonstrations, with DAgger-style learner-state coverage. It is not the final decision rule. The final value choice is made after candidate execution by successor-state evaluation, so the architecture is free to prefer multimodal or highly state-dependent values.

What this experiment tests

If the full policy beats myopicOnly, the critic is learning useful delayed consequences rather than merely reproducing immediate objective changes. If oracleValue remains strong but the learned policy fails, the bottleneck is in proposal coverage or successor valuation rather than variable selection. The diagnostic log reports proposal MAE, critic return MAE, and how often r+γV ranks the same candidate highest as a rollout-based return estimate.
