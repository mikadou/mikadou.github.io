Can the GNN learn a value rule from neighboring variables?

The handcrafted solver no longer uses a variable index to choose values. For a variable that must be greater, it looks through the constraint graph to the neighboring variable that must be smaller and proposes neighbor value + 2. Node index, normalized position, and graph-size coordinates are removed from the learner's node features.

Headline benchmark: —

1. The teacher is now local and relational

Construction proceeds left-to-right so the smaller-by-constraint neighbor already has a value. The first variable uses a fixed root mean of 0. Every later value is sampled around smallerNeighbor + 2. During repair, the teacher selects the greater-side node of a violated constraint and applies the same local rule.

2. No node ID or position feature

Variable nodes expose only type, assigned state, and current value. Constraint nodes expose type and satisfied / violated / unresolved status. There is no absolute index, relative index, normalized position, or graph-size coordinate. Ordering information exists only in the typed constraint edges: smaller side versus greater side.

3. The value learner must use message passing

The value head now reads a GNN embedding, not the selected node's raw features. In the bipartite graph the relevant variable is two hops away, so two message-passing rounds are the natural minimum. A separate GNN encoder is used for value prediction so learning the relational value rule cannot destabilize the already-easy repair-node classifier.

What would count as success?

If the network really learns neighbor + 2, it should generalize much better beyond the training chain lengths than the old position-regression MLP. The diagnostic log reports construction-value MAE, repair-value MAE, variable F1, solve rate, and probes showing the actual smaller-neighbor value, predicted mean, and teacher target.

RL is disabled for this experiment

First we re-establish pure imitation under the harder relational teacher. Once that works, RL can be added again without the positional shortcut.
