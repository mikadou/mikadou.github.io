Can a GNN represent the local-repair algorithm when its two subproblems are trained separately?

The last diagnostic showed two independent failures: repair scores barely separated valid endpoints from other variables, and even oracle endpoint selection failed because the learned value head collapsed at larger node indices. This version separates those tasks. A static learned positional head fits the teacher's N(2i,1) value rule, while a one-hop GNN is trained only to classify whether each variable touches a violated constraint.

Branch 1: static learned value rule

The teacher's value distribution depends only on node index: v ~ N(2i,1). It therefore no longer shares the dynamic post-message embedding with endpoint classification. A separate learned linear head sees absolute position i/99 and learns its own slope, bias, and Gaussian standard deviation before endpoint training begins. Because the head is linear, a rule fitted on indices 0…19 can extrapolate rather than bending or saturating at larger indices.

Branch 2: one-hop repair GNN

Constraint state is one-hot

Constraint nodes now use separate violated and satisfied bits rather than a signed +1/-1 scalar. This avoids asking a ReLU encoder to preserve the sign distinction before message passing.

A violated constraint is directly connected to its two variable endpoints, so one message round remains sufficient in principle.

More optimizer steps and stronger separation

Endpoint training uses batches of 16 repair states and four optimizer epochs per batch, giving roughly four times as many parameter updates as the previous run. Balanced binary cross-entropy is augmented with a logit-margin term that explicitly pushes positive endpoints above zero and negatives below zero instead of allowing every score to hover around 0.5.

Cleaner repair-state data

Training states begin as clean monotone chains and receive a small number of deliberately injected local violations. This produces controlled sparse endpoint labels without mixing in trivial construction states or relying on accidental violations from the teacher's Gaussian noise.

Diagnostics now isolate both branches

The copied log reports endpoint precision/recall/F1 plus average positive and negative classifier scores. oracleEndpoints uses exact repair endpoints with the learned value branch; oracleValue uses the learned endpoint classifier with exact teacher values. If either branch is still the bottleneck, the next log should identify it immediately. Value probes also report the learned slope/bias and extrapolation error.
