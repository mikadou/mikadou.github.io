1. Two-stage training protects the working components

About 60% of the requested examples pretrain the repair-variable classifier and Gaussian proposal head. Those weights are then frozen. Ranker gradients never touch them, so a good proposal cannot be destroyed by later successor-value training.

2. The ranker sees the actual successor and the changed node

Each candidate value is temporarily applied to the solver state. A separate GNN encodes that successor graph, and the ranker receives the selected variable's pre-message embedding, contextual embedding, the global solver node, and pooled graph context.

3. Whole candidate sets are supervised by teacher steps-to-go

For each training state and selected variable, the engine generates the same candidate family used by search. Each successor is labeled with the mean number of teacher actions still needed to reach feasibility, using shared random seeds across candidates. Unsolved continuations receive a large penalty.

4. Regression + listwise ranking

The network predicts remaining steps normalized by problem size. Training combines Huber regression with a listwise softmax loss that directly rewards the same candidate ordering used at inference. Diagnostics report stepsMAE, exact-best top1, pairwise ordering pairAcc, and the oracle target spread.

What would count as success?

The oracle already established that exact successor ranking can solve the current candidate/action system. In this experiment we want pairwise accuracy and top-1 ranking to rise during the RANK phase, followed by a non-zero closed-loop solve rate around the trained chain sizes.
