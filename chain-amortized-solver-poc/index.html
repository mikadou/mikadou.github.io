Learn which variable to repair and which value to try — without encoding the heuristic formula

This version removes the problem-specific linear value head. The common solver abstraction is now explicit: a typed GNN encodes the current variable/constraint graph, one shared head scores variable nodes, and a second shared head scores candidate values conditioned on the selected variable and graph state. The handcrafted N(2i,1) heuristic is used only to generate imitation examples; its formula is not present in the learned forward pass.

Common architecture across optimization problems

1. Graph state encoder

Variable and constraint nodes are embedded by a typed message-passing GNN. Constraint nodes expose generic solver-state information such as satisfied/violated status. Variable nodes expose assignment state, current value, domain-normalized features, and any model-supplied variable metadata.

The chain coordinate is present here only because the current teacher genuinely depends on that problem data. The network is not told that the relationship should be linear.

2. Variable action head

A shared scalar head scores every variable embedding. In this imitation experiment it is trained to rank variables touching violated constraints. In a later RL solver the same scores can be trained from search reward rather than teacher labels.

Generic value selection: score (state, variable, candidate value)

The value branch no longer outputs a slope, mean formula, or special distribution tied to node index. For a selected variable i, it evaluates candidate values using a shared MLP:

score(s,i,v) = MLP(local embedding before messages, contextual variable embedding, pooled graph embedding, candidate-value features).

Candidate features are generic numeric-domain quantities: normalized candidate value, change from the current value, and whether it leaves the value unchanged. During this toy benchmark the finite integer domain 0…1000 can be enumerated. In a larger solver the same interface can score a smaller candidate set produced by propagation, random sampling, neighborhood generators, or continuous proposal models.

Imitation labels are not architectural assumptions

The handcrafted teacher is still used to generate demonstrations so we can test representation without RL credit assignment. For each repair state, training provides good variable nodes and one demonstrated value. The value scorer sees that demonstrated value mixed with nearby and random negative candidates and learns to rank it. The network never receives the formula 2i as a model parameter or forward-pass rule.

Where this points next

The intended general solver action remains (variable node, value proposal). Imitation can initialize both heads from a classical heuristic or customer simulator; then RL can optimize the same action model against actual search improvement. The problem-specific code should increasingly live in the graph/features, domain interface, and simulator — not in the neural architecture.
