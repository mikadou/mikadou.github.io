Proof of concept · typed GNN + reinforcement learning

Can a factor-graph GNN learn a simple feasible construction?

Every variable now has the large integer domain 0…1000. The only constraints are x₀ < x₁ < … < xₙ₋₁. There are many feasible solutions — for example xᵢ = k·i for any positive k that stays inside the domain. The GNN receives no formula or solution label; it repeatedly chooses the full joint action (i,v) and learns only from generic feasibility feedback.

Graph representation

Two node types

Variable nodes Vᵢ represent xᵢ. Their features contain the variable type bit, normalized node ID i/(n−1), whether the variable is already assigned, and its assigned value when present.

Constraint nodes Gₖ represent xₖ₊₁ > xₖ. They have their own node type plus normalized constraint ID.

Typed message passing

Four directed edge types distinguish smaller-operand and greater-operand roles in both directions. Each edge type has its own learned message matrix.

Six residual message-passing rounds produce a 24-dimensional embedding for every graph node. There is no raw node-ID bypass around the GNN.

Sequential feasibility RL

Joint (i,v) action

The action head combines the GNN embedding of an unassigned variable Vᵢ with candidate value v/1000, then returns one scalar score. The policy therefore chooses both which variable to fix and which integer value to give it.

During training, greedy exploration scores a sampled set of joint actions; evaluation scores the full n × 1001 action space.

Feasibility only

During training, after a proposal xᵢ=v, a generic bound propagator checks the domains 0…1000 and all > constraints together with assignments already made. Reward is +1 if a completion still exists and −1 if the proposal makes the partial assignment impossible.

Accepted actions become part of the training state. There is no objective, no target assignment, and no reward for following a linear formula.

Open-loop evaluation

The feasibility propagator is not allowed to repair evaluation decisions. The trained GNN makes exactly one joint choice for each variable; after the complete assignment is produced, the benchmark simply checks whether it is strictly increasing. A family such as xᵢ=k·i is an easy reusable strategy, but the policy is free to discover any feasible monotone construction.

Everything runs locally in your browser. No training data or model state is uploaded.
