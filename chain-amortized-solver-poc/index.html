Proof of concept · generic learned repair actions

Learn which variable to repair, propose values, then score the proposals

The learned action model now combines both approaches. A typed GNN encodes the variable/constraint graph. One head scores variable nodes. For the selected variable, a generic proposal head predicts a Gaussian (μ,σ) only to generate promising candidate values. A separate shared scorer Q(s,i,v) then ranks those candidates and makes the final value decision. The Gaussian is therefore a proposal mechanism, not an assumption that the true value policy must be Gaussian.

Generic learned action structure

1. Pick a variable

The graph encoder produces contextual embeddings for all variable and constraint nodes. A shared variable head scores which variable should be repaired next. Its architecture does not know anything about monotone chains; the current graph/features merely provide the problem state.

2. Propose values

Conditioned on the selected variable embedding and global graph context, a shared head predicts μ and σ. Samples from that distribution are mixed with generic exploration candidates: domain bounds, the current value and nearby perturbations when assigned, and random domain samples.

3. Score each candidate value

The final decision is not made by the Gaussian. Every proposed candidate is scored by a separate shared network:

Q(s,i,v) = MLP(local embedding before messages, contextual variable embedding, pooled graph embedding, candidate-value features).

This lets the final policy represent multimodal or irregular preferences even when the proposal distribution itself is simple. If a future solver has better candidate generators — propagation, domain-specific neighborhoods, historical values, or another neural proposal model — they can be added to the same pool without changing the scorer.

Training remains generic imitation

The handcrafted heuristic is used only to generate demonstrated (state, variable, value) actions. The proposal head learns by likelihood of demonstrated values. The scorer learns to rank the demonstrated value against nearby and random negatives. The network is never given the teacher's 2i formula as part of its forward pass.

Value training deliberately mixes full repair states and partial construction states so the learned value mechanism is not tied to one solver phase.

Why keep both mechanisms?

ProposalOnly measures how good the learned (μ,σ) generator is by itself. The full policy uses the same proposal but lets Q(s,i,v) rerank the pool. If the full model beats proposalOnly, the scorer is adding useful non-Gaussian decision capacity. The log also keeps oracle-variable and oracle-value controls to isolate failures.
