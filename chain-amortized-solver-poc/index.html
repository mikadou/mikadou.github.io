Can one GNN message step identify the variables touching violated constraints?

The previous diagnostic showed that the value rule v≈2i was learned, while repair-variable probabilities stayed almost uniform. This version isolates that failure. Training uses only fully assigned repair states, deliberately injects local violations, and trains every variable with a balanced binary target: endpoint of a violated constraint or not. The value distribution is still learned separately so the resulting policy can be tested end-to-end against the handcrafted heuristic.

The repair decision is now a binary node-classification problem

Repair-only supervision

Every training example is a fully assigned chain with at least one violated adjacent constraint. Additional local violations are injected so the network sees a strong, frequent repair signal across all selected chain lengths.

Construction states are excluded from the endpoint loss. This removes the previous diagnostic artifact where candidate mass was trivially 100% because every unassigned variable was a valid construction choice.

Balanced binary cross-entropy

For each variable i, the target is simply whether it touches at least one violated constraint. Positive and negative losses are averaged separately and weighted equally, so sparse endpoints cannot be overwhelmed by the many non-endpoint variables.

At inference, variables scoring at least 0.5 form the predicted repair set. The solver samples uniformly from that set, matching the handcrafted heuristic's “pick any violated endpoint” behavior.

Why one message round should solve the classification task

Constraint nodes still expose +1 when violated, -1 when satisfied, and 0 when unresolved. A violated constraint node is directly connected to its two variable endpoints. With one typed message round, the endpoint predicate is therefore a one-hop graph computation. The 0-round setting remains a negative control.

Value learning is separated from endpoint learning

The value head still learns the teacher's N(2i,1) rule, but its loss has much smaller weight than the endpoint classifier. The copied benchmark log includes oracleEndpoints: exact repair-node selection combined with the learned value head. If that control solves while the full GNN does not, endpoint classification is still the bottleneck; if it also fails, value prediction is the issue.

Diagnostics

Training now reports endpoint precision, recall, and F1 on repair-only states. The copyable log includes endpoint probes, learned value predictions, closed-loop repair traces, and oracle-endpoint solve rates. This should make the next failure mode immediately identifiable.
